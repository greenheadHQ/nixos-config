# PR 본문 예시

대상 저장소의 템플릿이 우선한다. 아래 구조는 변경 규모에 맞게 선택한다. 의미 없는 항목을 채우기 위해 섹션을 만들지 않는다.

## 작은 변경

```markdown
설정 파일이 없을 때 종료하던 시작 명령이 기본값으로 계속 실행되도록 수정했습니다.

검증: 설정 파일이 있는 경우와 없는 경우를 실행해 정상 시작을 확인했습니다.
```

## 결정 근거가 필요한 변경

```markdown
인증 갱신 실패 후 같은 요청을 무한 재시도하던 문제를 수정했습니다. 이제 한 번 갱신한 뒤에도 실패하면 원래 오류를 반환합니다.

### 변경 이유와 선택

기존 재시도는 일시적인 토큰 만료를 복구하기 위해 도입되었습니다(관련 PR 링크).
갱신 자체의 실패까지 같은 경로로 재시도하면서 종료 조건이 사라졌습니다.
재시도를 모두 없애는 대안은 정상 복구도 막으므로, 갱신 횟수를 제한했습니다.

### 검증

만료 토큰의 정상 갱신, 갱신 실패, 갱신 후 재요청 실패를 확인했습니다.
운영 환경의 인증 공급자 장애 상황은 직접 실행하지 않았습니다.
```

CIR·ADR 명칭이나 비교 표는 선택의 복잡도와 저장소 관례에 맞춰 사용한다. 중요한 방어 로직의 이유는 필요하면 코드 옆에도 남긴다. 수동 확인이 필요하면 재현 가능한 절차와 기대 동작을 적고, 이미 수행한 검증과 구분한다.
