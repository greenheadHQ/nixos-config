# 근거와 재개 가능성

`create-issue`와 `write-handoff`가 공유하는 작성 기준이다. 문서 길이·고정 섹션·라벨 수보다 독자가 문제를 판단하거나 작업을 재개할 수 있는지를 확인한다.

- 문제와 목표를 먼저 설명하고, 실제 결과와 원하는 결과를 구분한다.
- 중요한 주장과 결정은 관련 코드·검증 결과·문서·이슈 또는 PR로 연결한다. 임시 경로나 squash 전 hash chain 대신 유지되는 참조를 사용한다.
- 재현이 필요한 경우 환경·입력·절차·기대와 실제 결과를 알아볼 수 있게 적는다. 모든 문서에 같은 필드 양식을 요구하지 않는다.
- 완료한 일·실행한 검증·남은 일과 제약을 구분한다. 실행하지 않은 검증을 통과했다고 쓰지 않는다.

## 라벨 체계 (Anti-hallucination)

E1: 확인하지 못한 주장은 불확실성을 명시하거나 삭제한다. 자연어로 상태가 명확하면 별도 라벨은 필요하지 않다. 긴 문서에서 구분에 도움이 될 때만 다음 라벨을 사용한다.

| 라벨 | 의미 |
|------|------|
| `[UNVERIFIED]` | 아직 확인하지 못함 |
| `[INFERRED]` | 확인된 근거에서 추론함 |
| `[CONFLICTING]` | 근거들이 서로 충돌함 |

## 근거 확인 기준 (E2)

이번 작업에서 확보한 직접 근거를 재사용한다. 출처가 없거나 충돌하거나 이후 상태가 달라질 수 있는 주장만 추가 확인한다. 확인할 수 없으면 그 범위를 명시한다.

이 기준은 [최종 본문 민감정보 검사](sanitization-checklist.md)를 생략하는 근거가 아니다. 외부 게시 대상·본문 전달·실패 시 보존은 각 게시 절차를 따른다.
